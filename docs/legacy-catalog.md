# Historical Catalog compatibility

The retained compatibility entry exposes catalogSupply, catalogStore, catalogContract, catalogGeneration, catalogMaterials and catalogBudget through the compatibility entry point. The native v1 entry point is unchanged.

The historical evopilot-harness wire identifiers, canonical digest serialization, resource budgets, closure verification, immutable content, CAS pointer switching, lock ownership/liveness checks, receipts, rollback, revocation and recovery algorithms remain compatibility protocols. Product error names identify Ontology. Validation does not relabel documents as native specifications/v1 and never grants human publication authority.

Call catalogSupply.semanticCatalogOperation with an explicit home, action and bound request fields. The home MUST be new Ontology-owned state outside the installed Ontology package. The API reads explicitly supplied config.yaml, harness-registry.yaml and the configured semantic policy; these historical filenames are retained protocol inputs, not default old homes. Imports create no workspace state. Own-package confinement is enforced. For current scoped product ownership, decisions and persistence, use the [owned Catalog service](catalog-service.md), whose SQLite recovery contract differs from this explicit file-backed library. Old operation authority is not imported. Store policy callbacks must come from trusted application code, never serialized input.

The Catalog extraction expanded that batch to 38 selected historical schemas, including six Catalog wire schemas. The Harness asset schema supports HarnessComponent, HarnessProfile and HarnessBundle only as READ-ONLY FOREIGN MATERIAL VALIDATION for complete pinned closure. Its semantic requirements digest verification is retained. This Ontology compatibility library exposes no Harness producer, engine, CLI or lifecycle API; DomainHarnessPack authoring remains rejected. Foreign assets keep their original identity, bytes and visibility and are not published by this migration.

Test fixtures contain a deterministic public api-gateway 2.3.0 bundle, its profile and engineering-validation component selected from verified historical assets. Source-relative paths, SHA-256 hashes and original YAML bytes are retained in tests/fixtures/harness-materials.json. These fixtures are excluded by the package files allowlist. Synthetic temporary membership indexes exercise the protocol without calling a Harness publisher.

Original contract, store and material assertions are retained with own-package imports. Focused supply tests cover prepare/preview, publication/readback, authorization/scope denial, repeat receipts, stale-head conflict, rollback/revoke and child-process crashes immediately before and after the pointer switch, including recovery/readback after response loss. The original contender fixture covers store CAS and crash tests.

The current [owned Catalog service](catalog-service.md) and [CLI](cli.md) provide scoped publication, readback, rollback, revocation and receipt reconciliation. Parent Preview MCP routing and unified Expert guidance are implemented. Their existence does not establish all historical supply IPC races, Host cancellation/disconnect paths, cleanup failure scenarios or renderer behavior.

External legacy Harness material still requires an explicit trusted application resolver. Default CLI/Preview deployments configure none. See the [integration boundaries](service.md#preview-integration-and-provider-boundaries) and [independent technical baseline](../README.md). Actual Desktop/Host full-journey acceptance, full migration, E03/E10 and source-ledger closure status must be obtained from a separate local acceptance report bound to the exact candidate; without that report, no acceptance can be claimed.

For the live inventory and extraction details, see [current schema provenance](../provenance/legacy-schema-sources.json), [Catalog provenance](../provenance/legacy-catalog.json) and the [explicit derivation bridge](legacy-migration.md). The 38-schema count describes that extraction set, not a fixed live total. Original source commits, licenses and provenance remain retained.
