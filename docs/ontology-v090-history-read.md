# Limited Preview: historical reads / 限定 Preview 历史读取

OL06 observes one explicitly selected historical-format v1 asset and its original producer receipt through the **new installed package's public reader**. The data may be fictional and created today by a verified, previously published original package. It does not perform installation upgrade, migration, old-engine execution or business reconstruction. The original 143-case target and unresolved MAINT-02 failure remain intact. Earlier-candidate upgrade is deferred, not passed.

OL06 仅验证明确选定的历史格式 v1 资产及其原生产器 receipt，经由**新安装包的公开读取 API**读取。数据可以是今天由核实的旧版正式发布原包产生的虚构资产。它不执行安装升级、迁移、旧推理器或业务重建。原 143 项目标与 MAINT-02 未解决失败继续保留；较早候选升级是暂缓，不能计为通过。

## What counts as historical evidence / 合格历史证据

Two explicit origins are accepted. `RETAINED_ORIGINAL_OUTPUT` binds retained `asset.inspect` output and its original `asset.publish` receipt. `PINNED_PUBLISHED_PRODUCER_FIXTURE` binds fictional output actually generated by a verified previously published package, its `asset.put` receipt, and optionally a separate pure `buildDelivery` output. Both require the original producing archive and exact source/output digests. The producer package version and historical delivery interface version are separate: this reader admits delivery interface `0.1.0`, `0.1.1` and `0.2.0`. A version label changed on current output is not historical compatibility evidence. Repository `historical-v020` runtimes and collector test doubles are synthetic unit evidence only.

支持两种明确来源：`RETAINED_ORIGINAL_OUTPUT` 绑定保留的资产导出及原始发布 receipt；`PINNED_PUBLISHED_PRODUCER_FIXTURE` 绑定经核实的已发布旧原包实际产生的虚构资产、`asset.put` receipt，以及独立的纯 `buildDelivery` 输出。两者都需要原生产包归档和确切来源/输出摘要。生产包版本与交付格式版本不同；此 reader 支持交付格式 `0.1.0`、`0.1.1`、`0.2.0`。给当前产物改版本号不构成兼容证据；仓库 `historical-v020` 代码和适配器测试替身只能用于合成单测。

Integration must verify that the archived producer and receipt really produced the selected output; a self-written version label is insufficient. This technical provenance check does not create an additional semantic or user-approval step. This collector returns `OBSERVED`, `technicalStatus: PASS`, `acceptance: REVIEW_REQUIRED`; it never emits an accepted OL06 result or release authorization. The integrating gate binds provenance, exact candidate, required standards report approval and this observation. Before standards admission, observations are diagnostic only.

集成时须核实归档生产包与 receipt 确实产生了选定产物；自写版本声明不足以证明。这是技术来源检查，不增加额外语义批准或用户审批。适配器只返回技术观察 `OBSERVED` / `technicalStatus: PASS` / `acceptance: REVIEW_REQUIRED`，不会自行给出 OL06 验收或发布授权。集成门禁仍须绑定来源、确切候选、标准报告批准与本次观察；标准准入之前的运行只能作为诊断。

## Prepared owner / 已准备的隔离 owner

For `PINNED_PUBLISHED_PRODUCER_FIXTURE`, initialize a completely new private owner with the verified old package's public `createOntologyService`, then call `asset.put`, `asset.inspect` and `receipt.inspect` for fictional v1 input. A separate `buildDelivery(model)` result is a pure verification sample, with `authority`, `businessConfirmed` and `released` all false. Do not call `asset.decide` or `asset.publish`, or invent a human decision. Close the owner before new-package reading. On a different OS/Host, regenerate the fictional owner through the same pinned published package API; do not rewrite `canonicalRoot` or fake relocation evidence. No existing business workspace is necessary.

`PINNED_PUBLISHED_PRODUCER_FIXTURE` 使用已核实旧包的公开 `createOntologyService` 初始化全新私有 owner，对虚构 v1 输入调用 `asset.put`、`asset.inspect`、`receipt.inspect`。独立 `buildDelivery(model)` 仅作纯校验样本，其 `authority`、`businessConfirmed`、`released` 均为 false；不调用 `asset.decide` / `asset.publish`，不编造人工决定。关闭 owner 后再用新包读取。换 OS/Host 时用同一锁定发布原包的公开 API 重新生成虚构 owner，不改 `canonicalRoot` 或伪造 relocation；无需现存业务 workspace。

Provide a quiescent, checkpointed **existing isolated** historical workspace. Prepare it separately through a reviewed public owner operation and retain its receipt. Preserve original business records and original export files. Do not edit the workspace identity, SQL records or relocation signatures to make it open; do not copy credentials or keys implicitly. Relocation may require original-host evidence and keys, so portability to another Host is not promised. The collector does not open the original daily installation, prepare a copy, call a migration API or generate historical data.

提供已停止写入并完成 checkpoint 的**既有隔离**历史 workspace，事先通过经审阅的公开 owner 操作准备并保留 receipt。保持原始业务记录与导出文件；不得为使副本可打开而改身份、SQL 记录或 relocation 签名，不得隐式复制凭据或密钥。Relocation 可能依赖原 Host 证据与密钥，因此这里不承诺跨 Host 可移植。适配器不会打开日常安装，也不会准备副本、调用迁移或生成历史数据。

The existing reader, and even SQLite read-only connections in WAL mode, can create empty journal/SHM metadata. The collector permits empty WAL/journal files and bounded regular SHM metadata; it refuses nonempty write journals without checkpointing or deleting them. The separately prepared owner must remain quiescent. The collector verifies all retained SQL table values/schema/state version, workspace marker and Ontology blob bytes before and after; it does not promise identical database container bytes after the product opens it. Original export/provenance/package files are read only and their byte hashes must remain unchanged. All table rows are bounded at 4,096 per table / 20,000 total, records at 32 MiB, and asset blobs at 64 MiB.

现有 reader，甚至 WAL 模式下的 SQLite 只读连接，可能产生空 journal/SHM 元数据。适配器允许空 WAL/journal 与有界正规 SHM，拒绝非空写入日志，不自行 checkpoint 或删除；已准备 owner 必须保持停止写入。适配器前后核对所有保留的 SQL 表值/结构/状态版本、workspace 标记与 Ontology blob；不承诺产品打开后数据库容器文件逐字节相同。原始导出、来源记录和生产包始终只读且摘要必须保持。每表最多 4,096 行，总共 20,000 行，记录 32 MiB，资产 blob 64 MiB。

## Input contract / 输入合同

Run with pinned Node 24.14.0:

```sh
node tests/acceptance/v090/limited-history.mjs --input /absolute/private/input.json --output /absolute/private/new-observation.json
```

Every reference below is `{ "path": "/canonical/absolute/file", "digest": "sha256:…" }`. Paths must be regular, unlinked, existing files; original evidence must be outside the isolated workspace. Runtime, workspace and output must be outside source and separate. Output must be new. Input is private; do not commit real asset data, local paths or credentials.

下列引用都采用 `{ "path": "/canonical/absolute/file", "digest": "sha256:…" }`。引用必须是规范绝对路径的普通无硬链接文件；原始证据放在隔离 workspace 之外。Runtime、workspace、输出须与源码及彼此分离，输出文件必须不存在。输入保持私有，不提交真实业务数据、本地路径或凭据。

```json
{
  "schema": "ontology-limited-history-input/v1",
  "caseId": "OL06",
  "candidateDigest": "sha256:<new candidate archive digest>",
  "sourceCommit": "<40 hex new source commit>",
  "runtime": { "root": "/isolated/installed-runtime", "digest": "sha256:<runtime inventory digest>" },
  "history": {
    "export": { "path": "/evidence/original-asset.json", "digest": "sha256:<bytes>" },
    "receipt": { "path": "/evidence/original-publish-receipt.json", "digest": "sha256:<bytes>" },
    "provenance": { "path": "/evidence/provenance.json", "digest": "sha256:<bytes>" },
    "producerArtifact": { "path": "/evidence/old-package.tgz", "digest": "sha256:<archive bytes>" },
    "workspace": {
      "root": "/isolated/prepared-owner", "workspaceId": "original-owner-id",
      "businessDigest": "sha256:<historicalBusinessSnapshot result digest>",
      "preparation": { "path": "/evidence/preparation.json", "digest": "sha256:<bytes>" }
    },
    "scope": { "visibility": "private", "projectId": "original-project" },
    "foreignScope": { "visibility": "private", "projectId": "absent-project" },
    "id": "original-asset-id", "version": "original-asset-version", "requestId": "original-publish-request"
  }
}
```

`provenance.json` requires `schema: ontology-historical-output-provenance/v1`, the selected `origin`, `exportDigest`, `receiptDigest`, `recordedAt`, and `producer: {packageVersion, deliveryInterfaceVersion, sourceCommit, artifactDigest}`. The producer commit and archive must differ from the new candidate. For a draft `asset.put` receipt, add `history.delivery` as a separate file reference and bind its byte hash in provenance `deliveryDigest`. The draft record must have `delivery: null`; the pure delivery must contain the same model without business approval. `PINNED_PUBLISHED_PRODUCER_FIXTURE` additionally requires a `publicationEvidence` reference to the original published `evopilot-release-readback/v1` record, matching source commit, archive digest and non-draft tag identity.

`preparation.json` requires `schema: ontology-historical-read-preparation/v1`, `mode: EXISTING_ISOLATED_OWNER` for retained records or `FRESH_PUBLISHED_PACKAGE_OWNER` for newly generated old-package fixtures, `workspaceRoot`, `workspaceId`, `businessDigest`, `exportDigest`, `receiptDigest`, `noBusinessRewrites: true`, `quiescent: true`, `dailyInstallation: false`, and a pinned `ownerPreparationEvidence` reference. The latter retains actual generator/API traces, original package/source references and input digests. These declarations are checked against files and observed business rows. The exported `historicalBusinessSnapshot(root)` helper reads only an already prepared isolated fixture to calculate its bound digest; it is not a preparation or migration API.

`provenance.json` 和 `preparation.json` 的上述字段分别绑定历史来源与已准备 owner；其中声明必须经独立审阅核实，不能用自写声明替代真实操作证据。导出的 `historicalBusinessSnapshot(root)` 只读取已准备的隔离夹具以计算绑定摘要，不是准备或迁移 API。

## Observations and current gap / 检查与当前缺口

The observer requires exact asset and receipt reads, positive delivery verification, cross-project / cross-visibility / foreign-receipt denial, tampered-delivery rejection, unknown-model-schema rejection, retired-mutation refusal, and unchanged original evidence/business inventory. The negative calls use the selected new public API. No old engine is admitted or executed. Unsupported v2 schema digests and old installation startup are outside this narrowly selected v1 reader claim.

观察必须覆盖资产/receipt 精确读回、交付校验、跨项目/visibility/receipt 拒绝、篡改拒绝、未知模型 schema 拒绝、历史 mutation 拒绝以及业务/原证据保持。负向调用同样使用新公开 API，不准入或执行旧推理器。未知 v2 schema 与旧安装启动不在本次窄化 v1 reader 声明内。

An old-package fictional fixture can establish format compatibility without daily data, but its preparation is not itself new-candidate read acceptance. OL06 remains **NOT_EVALUATED** until the exact installed candidate completes these observations under the required admission. Missing evidence, relabeled current outputs, collector test doubles, stale or mismatched input produce `BLOCKED`, not PASS. A successful collector unit test cannot fill this evidence gap.

旧原包产生的虚构夹具可用于格式兼容检查，无需日常数据；但准备夹具不等于新候选读取验收。确切新安装候选在要求的准入下完成观察之前，OL06 保持 **NOT_EVALUATED**。缺失证据、改版号伪装的新产物、collector 测试替身、过期或不一致输入只能 BLOCKED；单测不能填补此缺口。
