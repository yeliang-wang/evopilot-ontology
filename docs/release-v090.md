# v0.9 distribution and release sequence

This guide describes release requirements, not publication status. The [release index](https://github.com/yeliang-wang/evopilot-ontology/releases) records actual tagged distributions. The package identity is `@evopilot-next/ontology@0.9.0`; the archive is `evopilot-next-ontology-0.9.0.tgz`. Node is pinned to 24.14.0. The standalone CLI is `evopilot-ontology` and the independent plugin is `evopilot-ontology-preview`.

## Required order

1. Freeze the package, source revision, dependency lock, native artifacts and source/notice companions, configuration, original official cases and independent evaluators. Install the exact package in isolation through public product entry points.
2. Execute all declared standard families through installed CLI, HTTP or MCP. Retain original inputs, product observations and comparisons; SHACL requires both boolean and complete report agreement. Present the complete [standards report](standards-evaluation-v090.md).
3. Obtain the actual user's approval of that exact report and candidate. An implementation approval, technical PASS or agent conclusion cannot replace it.
4. Run the original 143 product acceptance variants with the same admitted basis. Preserve pre-release and post-release distinctions; missing collectors or unexecuted required cases are not PASS.
5. Present exact source, CI, distribution and pre-release results for a separate release decision. Publish only the authorized candidate, retaining checksums, source revision, locked dependency material and native source/notice closure.
6. Download the published artifacts, verify their hashes, install and perform the required public readback. Only then perform the separately inventoried P6 test-asset reset. Do not rebuild business assets automatically.

Any change to the reviewed package, corpus, toolchains/configuration or report requires reevaluation and a new report review. Product and semantic review decisions remain separate from software publication. No production deployment or graphical UI is included.

## Distribution identity and platform

The pinned offline native catalog selects Linux ARM64, glibc 2.28 or newer, Temurin 21.0.13+9 and CPython 3.12.12 with locked SHACL dependencies. Bounded workers require a verified systemd user manager. The [managed toolchain guide](managed-toolchains-v090.md) defines all thirteen component/source/notice materials and their exact packaged identities. A catalog entry is not platform acceptance; the candidate must run in that environment.

The product package excludes development tests and scripts but includes compiled code, original native adapter sources, schema/specifications, governance, plugin and documentation. No private workspace, credential, actual user decision or acceptance ledger belongs in the public archive. Source CI and local development tests produce evidence; neither is the formal product acceptance collector nor publication authority.

The root legacy SDK and `evopilot-next-ontology` CLI retain the v0.8.3 interface identity. Use the independent installed `runtime-inspect` result to identify the v0.9.0 package and exact Node/files. Historical root exports do not advertise the native v2 capabilities.
