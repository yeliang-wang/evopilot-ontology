# Scoped Catalog service

> Historical interface reference. Corrected-v1 work uses the [native service](native-service.md) and [current specification](../specifications/v1/README.md). Retired JSON, producer, Catalog and classification mutation operations are rejected; descriptions below explain retained historical records, not current execution authority.


The `@evopilot-next/ontology/service` entry (compiled `dist/service.js`) implements ten `semantic.catalog.*` routes using the existing owned compat `assembleSemanticGeneration` and `resolveSemanticGeneration`. Compat libraries, schemas, historical APIs and their recovery capabilities remain unchanged. The owned lifecycle, [CLI](cli.md), parent Preview MCP routing and unified Expert guidance are implemented. External legacy Harness materials require an explicit application resolver; neither the default Preview daemon nor the standalone CLI supplies it. See [integration boundaries](service.md#preview-integration-and-provider-boundaries).

All requests use the service envelope and exact `{visibility, projectId}` scope. Mutations additionally require `requestId` and global `expectedRevision`. Inputs are closed typed JSON, never legacy home, registry, policy or material paths. Discovery is pure.

| Operation | Exact input | Result |
| --- | --- | --- |
| semantic.catalog.preview | PUBLISH parameters below | generationDigest, expectedGenerationDigest, inputDigest, transitionDigest, head, authority:false |
| semantic.catalog.transition-preview | ROLLBACK or REVOKE parameters | Same digest preview, with full validation |
| catalog.prepare | Any action parameters | PREPARED plan, exact reviewDigest and dependencies |
| catalog.decide | planId, reviewDigest, decision:APPROVE\|REJECT, evidenceRef | Local uid decision and server time |
| catalog.plan-inspect | planId | Scoped verified plan |
| semantic.catalog.publish | planId | Durable pointerDigest and generationDigest receipt |
| semantic.catalog.rollback | planId | Durable rollback receipt |
| semantic.catalog.revoke | planId | Durable revocation receipt |
| semantic.catalog.inspect | catalogId | Verified pointer, generation, material pairs and reconstructed sets; EMPTY if absent |
| semantic.catalog.readback | requestId | Exact original scoped Catalog mutation receipt, including immutable material verification |
| semantic.catalog.recovery-inspect | catalogId | CLEAN/reconcilable after verifying revisions and original receipts |
| semantic.catalog.recovery-readback | requestId, intentDigest | COMMITTED or serialized NOT_COMMITTED |
| semantic.catalog.recover | requestId, intentDigest | Own idempotent reconciliation receipt for the original request |

PUBLISH parameters are `{catalogId, action:'PUBLISH', expectedHead, sets}`. ROLLBACK uses `{catalogId, action:'ROLLBACK', expectedHead, targetPointerDigest}`. REVOKE uses `{catalogId, action:'REVOKE', expectedHead, revokedDigests}`. `expectedHead` is exactly `EMPTY` or the current pointer digest. Catalog ids are service slugs. Revocations must be nonempty, unique, known current object digests. Initial empty publication is rejected. Revocation removes complete sets containing the dependency; rollback selects a verified prior revision of the same scoped catalog. Cumulative revocations survive every action, and revoked entries cannot return.

Each set contains `artifactSet`, `closure`, `foundation`, `proposal`, `packs`, `profile`, `index`, `projectionSet`, `roundTripReport`, `incremental`, `full`, `support`, `harnessAssets`, optionally `priorSnapshot` and `basePackSet`. The full documents are checked by the unchanged compat validators, deterministic assembly and resolution. Artifact, approved Proposal, Closure, retained foundation, published Pack material and rollback evidence must match real scoped producer history and consumed local decisions, including verified blobs. Caller status labels and old document APPROVED fields grant no authorization. Public scopes reject nested private material; every project/workspace binding must match. DomainHarnessPack is not an Ontology input.

The embedding application may call `createOntologyService(options, {resolveLegacyHarness})`. This second argument is trusted application code; JSON options and requests cannot inject functions, callbacks, configuration or lookup paths. The synchronous resolver receives `{reference:{kind,id,version,digest},scope,workspace}` and must return `{verified:true,entry,document,scope,workspace}` with exact full identity. The entry/document must also pass unchanged compat schema, digest and published-lifecycle validation. Absent, unknown, mismatched, failing or Promise results reject; late Promise rejection is consumed. The resolver is read-only and is called again during stored validation. Current tests inject explicitly synthetic known material. The parent factory forwards the actual trusted-provider keys with validation; this is not a Harness material provider implementation. The global legacy query foreign-document prohibition is unchanged.

Plans bind workspace identity, scope, action, expected head, exact materials, generation and transition digests, and current producer dependencies. Decision/execute recompute these bindings. Publication actor/time come from the server. SQL atomically updates head, immutable revision reference, consumed plan, original receipt and audit. Blobs are created and verified before commit; failed transactions can leave unreferenced immutable bytes. Earlier blobs/revisions are preserved. Reads and idempotent publication replies verify retained material even after later head changes.

Recovery deliberately differs from the old file-backed Catalog backend. SQLite has no separate publication lock to clear and no resumable external work. Readback serializes with writers and verifies the exact original scoped request id and intent digest. `recover` has its own different requestId and expectedRevision; it records COMMITTED with the original pointer or NOT_COMMITTED when absence is established after serialization. NOT_COMMITTED describes that observation, not a reservation against a future new submission. It never dispatches, republishes or force-unlocks. Conflicts, corrupt material, provider unavailability and other unresolved failures throw `UNKNOWN` with `causeCode`; callers must retain uncertainty. A reconciliation changes only the global revision/receipt/audit, never the Catalog head. The intent digest is the original receipt's requestDigest (hash of operation, scope and input; expectedRevision is excluded).

Limits share the existing 512 KiB/20,000-node/depth-48 request, 8 MiB state, 10,000 receipts and 32 MiB receipt budgets. Additional maxima are 16 sets per generation and 1,000 each of plans, revisions, scoped catalog heads and cumulative revoked digests. Unchanged compat material/entry/edge limits also apply. No caller may raise them. Old schema-v1 state gains optional Catalog collections lazily.

For Catalog, the trusted provider object accepts the optional function-valued `resolveLegacyHarness` data property. The shared factory also accepts `resolveClassificationSource`, `classificationAdvisor` and the typed `classificationModel` described in [Classification service](classification-service.md). The object must be plain or null-prototype. Symbols, other keys and accessors reject without invoking getters. Returned structures are bounded before reading fields; genuine Promises are detected with `isPromise` and their rejection consumed through `Promise.prototype.then.call`. Malformed requests remain `INVALID_REQUEST` before validation, including malformed recovery requests; only safely validated recovery operations receive `UNKNOWN` wrapping.

Repeated plans with identical subjects remain legitimate. Prepare receipts bind their exact planId and original request digest. Decision receipts use the audited original decision fields and request digest to identify the exact scoped plan, preserving historical decisions and idempotent replies after subsequent decisions or consumption.

Verification coverage includes complete owned-material publication, rollback between verified generations, cumulative revocation, readback/restart, scope/CAS rejection, descriptor safety, repeated-plan receipts and immutable-material corruption. See the [source validation workflow](../CONTRIBUTING.md). Synthetic test materials do not establish an external Harness provider.
